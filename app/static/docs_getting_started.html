Getting started

Everything you need to send your first decision through CGC Core and receive a webhook back.

1. Get an account

Sign up with an email and password:

curl -X POST https://cgc-cre.vercel.app/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "a-strong-password-12+chars"}'

Then sign in to get a bearer token:

curl -X POST https://cgc-cre.vercel.app/auth/signin \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "a-strong-password-12+chars"}'
# -> { "access_token": "eyJ..." }

2. Claim your app and get an API key

An app_source is your app's identity in CGC Core — lowercase letters/digits/hyphens, 3–50 characters. Claim one with your bearer token:

curl -X POST https://cgc-cre.vercel.app/tenants/self-signup \
  -H "Authorization: Bearer eyJ..." \
  -H "Content-Type: application/json" \
  -d '{"app_source": "my-app"}'
# -> { "key": "cgc_live_...", "key_prefix": "cgc_live_XXXXXXXX" }
The key field is shown exactly once. Store it now — it can only be revoked and replaced later, never recovered. Manage it any time at /dashboard/account.

3. Send a decision

Use the API key as your bearer token from here on — it's bound to your app_source, so you don't need to pass it again:

curl -X POST https://cgc-cre.vercel.app/governance/decision \
  -H "Authorization: Bearer cgc_live_..." \
  -F "org_id=customer-42" \
  -F "action=classify_transaction" \
  -F 'input_data={"amount": 500, "category": "office_supplies"}' \
  -F "user_email=you@example.com" \
  -F 'data_domains=["financial"]' \
  -F "area=FINANCE"

The response includes approved, outcome (APPROVE / REJECT / REQUIRE_HUMAN), the full module score breakdown, and a cryptographically signed decision_artifact (Proof of Decision). See /governance/scoring-methodology for exactly how the outcome is computed.

4. Set up a webhook (optional)

Register a URL to receive a signed POST every time a decision resolves for your app_source, instead of polling:

curl -X POST https://cgc-cre.vercel.app/tenants/my-apps/my-app/webhook \
  -H "Authorization: Bearer eyJ..." \
  -H "Content-Type: application/json" \
  -d '{"url": "https://your-app.example.com/webhooks/cgc-core"}'
# -> { "secret": "whsec_..." }  -- shown once, store it

Every delivery includes an X-CGC-Signature: sha256=<hex> header — an HMAC-SHA256 of the raw request body, keyed with your webhook secret. Verify it before trusting the payload:

import hmac, hashlib

def verify(body: bytes, signature_header: str, secret: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header)
Delivery is best-effort with a 5-second timeout and no retry queue yet — a slow or failing endpoint never blocks or delays your /governance/decision call beyond that timeout, but a missed delivery isn't retried. Check last_delivery_status via GET /tenants/my-apps/{app_source}/webhook if you suspect one was missed.

Your current usage against your quota is shown live on /dashboard/account. Upgrade from there — no admin action needed.

Key rotation

Rotate your key any time from /dashboard/account — this revokes the old key and issues a new one immediately. Keys older than 90 days show a "Rotate soon" badge as a reminder; nothing rotates automatically or expires on its own.
